### 2&#41; 크로스 플랫폼 개발(Cross-Platform Development)이란?
- `크로스 플랫폼 앱`은 `하나의 코드로 작성`하여 ios와 Android `두 가지 플랫폼 모두`에서 작동하도록 만드는 앱

---

### 2-1&#41; 웹 개발자에게 친숙한 개념
- `반응형 웹 디자인` : 하나의 HTML/CSS 코드로 데스크톱, 태블릿, 모바일에서 모두 적용
- `JavaScript` : Chrome, Firefox, Safari 등 모든 브라우저에서 동일한 코드 실행
- 모바일 앱에서도 같은 철학을 적용한 것이 바로 `크로스 플랫폼 개발` <br /> → 웹의 `브라우저`가 `운영체제`로 바뀐 것뿐

---

### 2-2&#41; 크로스 플랫폼 개발의 장점
1. `코드 재사용` : 대부분의 코드(약 70~90%)를 두 플랫폼에서 함께 사용 <br /> → 개발 시간과 비용이 절약
- 실무 예시 : 로그인 기능을 한 번만 만들면 iOS와 Android 모두에서 작동 
- 비용 절감 : 개발 시간이 절반으로 줄어들고, 유지보수 비용도 크게 감소

2. `빠른 출시`: 한 번의 개발로 두 플랫폼에 동시에 앱을 출시할 수 있어 시장 진입 속도가 빠름 
- 비즈니스 관점 : 스타트업이나 MVP(Minimum Viable Product) 개발에 특히 유리함
- 예시 : 아이디어를 검증하기 위해 빠르게 두 플랫폼에 동시 출시할 수 있음

3. `관리의 용이성` : 버그 수정이나 기능 추가를 할 때도 하나의 코드만 수정 → 관리가 쉬움
- 실무 시나리오 : 사용자가 "로그인 버튼 색상 변경"을 요청하면, 한 곳만 수정하면 iOS와 Android 모두에 반영됨

---

### 2-3&#41; 크로스 플랫폼 개발의 단점
1. `성능의 한계 (과거)`
- 과거에는 네이티브 앱에 비해 성능이 약간 떨어지고 복잡한 애니메이션 구현이 어려웠음 <br /> → 하지만 React Native와 같은 최신 기술은 이 격차를 크게 줄어듦 
- 현재 상황 : React Native는 실제 네이티브 컴포넌트를 사용, 대부분의 앱에서 성능 차이를 느끼기 어려움
- 예외 : 초고성능이 필요한 게임이나 실시간 영상 처리 앱은 여전히 네이티브 개발이 필요함

2. `기기 기능 접근의 제약`
- 간혹 특정 기기의 아주 깊숙한 네이티브 기능에 접근하기 위해 추가적인 설정이나 코딩이 필요할 수 있음
- 현실 : 대부분의 일반적인 앱 기능(카메라, GPS, 알림 등)은 크로스 플랫폼 도구에서 잘 지원됨
- 해결책 : Expo나 React Native 커뮤니티에서 제공하는 라이브러리로 대부분의 기능을 쉽게 사용가능
